# Speech-only migration spike and approval plan

Checked 2026-10-17. Partial planning/contract work for [#26](https://github.com/jeanbrianc/virtual-school/issues/26). Keep the issue open. No model substitution, new credentials, provider request, infrastructure change or deployment is performed by this branch.

## Verified lifecycle and API contract

The [official October 1 notice](https://developers.openai.com/api/docs/deprecations#2026-10-01-text-to-speech-models) still lists January 6, 2027 shutdown for `tts-1`, `tts-1-hd` and both dated `gpt-4o-mini-tts` snapshots, recommending `gpt-realtime-2.1-mini`. The current repo's default is the deprecated `gpt-4o-mini-tts` alias; deployed private configuration has not been inspected here. Do not assume an alias avoids the shutdown.

The [Realtime WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets?voice-api=realtime) specifies a server-side authenticated `wss://api.openai.com/v1/realtime?model=…` connection. The [client event contract](https://developers.openai.com/api/reference/resources/realtime/client-events) supports explicit `session.update`, `response.create`, response cancellation, text-only input, no automatic VAD turn, bounded output tokens and PCM 24 kHz. [Conversation guidance](https://developers.openai.com/api/docs/guides/realtime-conversations) describes base64 audio delta events plus final response/transcript events. It does not establish `/audio/speech` compatibility for the replacement. This branch explicitly refuses `gpt-realtime…` in the legacy speech route instead of silently sending it to the wrong API.

## Recommended architecture, pending owner approval

Keep browser→helper `/v1/speak` as a bounded HTTP request. Keep the provider credential exclusively server-side, using the existing key source after approval. The helper would create a short-lived WebSocket per approved line; no browser ephemeral credential, WebRTC audio track, microphone acquisition, transcript ingestion, tools, session history, continuous listening or open-ended conversation. Only the already-consented approved teacher text plus nonpersonal voice instructions goes to the same provider. Material transport/retention/cost behavior must be disclosed before enabling the new adapter.

Use `response.create` with a fresh explicit text input and `conversation: none`; set tools empty, tool choice none, input transcription and turn detection null. Reuse each teacher's explicitly supported current voice (`cedar`, `verse`, `coral`, `marin`); no automatic voice substitutions. Retain original language, respelled pronunciation and safety-approved text. A session cannot switch voices after audio, so per-line sessions avoid history/voice mixing. Reuse would need separate review and privacy/cost tests.

A Realtime prompt is generative; instructions are **not a guarantee** of verbatim read-aloud. Buffer a maximum of 30 seconds of PCM, require successful completion and exact transcript equality (Unicode NFC + whitespace normalization only), then wrap PCM as mono 16-bit 24 kHz WAV for existing HTML audio playback. Discard/refuse divergent, missing, failed, truncated, overlong or late output and use built-in speech. The model-produced transcript is still not proof of the audio's exact spoken content: human listening/pronunciation acceptance remains a release gate. If that cannot meet the product requirement, leave natural speech disabled and retain built-in read-aloud.

Tradeoff: buffered verification sacrifices time-to-first-audio and uses more helper memory versus streaming. Streaming before verification could speak unapproved words and is not recommended for this child-facing path. A WebSocket adapter needs bounded connection/response deadlines, size limits, validated session configuration, failure categories and guaranteed close in finally. Check existing Lambda timeout/response limits before selecting budgets. No new persistent websocket server is assumed. Existing HTTP client cancellation may not reach an executing Lambda, so server deadlines and durable quota accounting remain necessary; do not promise an aborted browser request costs nothing.

Close/interruption sends `response.cancel` for that response, closes the socket, stops playback/revokes object URLs and invalidates the request generation. Late data cannot play or populate cache. No automatic paid retry or provider fallback. Provider 429/cooldown and built-in fallback survive. A parent generation test remains the existing short nonpersonal sample; configured, generated and audibly tested are distinct statuses.

## Offline code spike

`spikes/realtimeSpeech.ts` is deliberately unreferenced by production code. It creates the documented event plan and consumes synthetic response events. It implements bounded audio buffering, response-ID isolation, duplicate event suppression, transcript matching, WAV framing and cancellation. It has no socket implementation or secret handling, so a passing test **does not prove the provider accepts the request**, latency, pronunciation, audible faithfulness, actual token usage or phone decoding.

Its cache identity includes algorithm version, model, voice, full instructions, format and approved text. A production cache must additionally include the helper endpoint and a verified configuration revision, with old cache namespace deletion on migration/consent withdrawal. Hashing a line is not anonymization of its audio; preserve existing browser-only retention/deletion disclosure. The current runtime cache still keys by teacher + text and lacks model/instructions revisioning. That is an explicitly open migration requirement, not claimed fixed here. Durable request IDs and a shared atomic ledger are also required to prevent repeated paid dispatch across concurrent helper instances/retries; a browser cache alone is insufficient.

At 30 × 1,024 audio output tokens the output-only estimate is $0.6144, plus text/other applicable charges. Reserve conservatively before each request, include failures/unknown results, and stop before the approved total. Confirm any provider terms, new permissions or architecture changes separately. No paid run has been performed.

## Acceptance and rollout before January 6

1. Owner reviews the speech-only transport, retention/disclosure, quota integration and exact paid-test budget. Keep legacy defaults unchanged until then.
2. Implement transport behind an explicit disabled-by-default adapter selection, finish model/instruction-aware cache invalidation and durable request deduplication. Add live contract checks with synthetic lines only after approval. Never infer consent to audio input from speech output consent.
3. Desktop Chrome/Edge/Safari and real iPhone Safari/Android Chrome acceptance: decode WAV, muted/zero volume, audio device unavailable, autoplay rejected, Close/Back/reopen during connect/generate/play, repeated clicks, offline/provider failures and bounded cooldowns. Include pronunciation, original language and voice identity. Synthetic fixture decode tests are not real-device acceptance.
4. Review verified-text mismatch/fallback rates, p50/p95 full latency, duration and reconciled usage. A failure blocks enablement. Retest parent configured-versus-tested copy and nonpersonal voice sample. Keep local lessons/read-aloud usable through all failures.
5. Aim for owner-approved limited rollout by December 1, with a December 15 decision to keep the new path or disable optional natural speech. This schedule is a recommendation, not a deployed automation. After January 6 rollback is built-in speech, never a retired TTS model.
